# AI 学习音频 Web 播放器设计规范（Spec）

## 1. 概述与目标

本项目旨在为个人打造一个美观、高效、专注于学习场景的 Web 音频播放网站。用户可将桌面上的 `.m4a` 格式音频文件归档入库，并通过 GitHub Pages 免费静态托管，在任意 PC 或移动端（手机/平板）浏览器中随时随地收听。

### 核心设计原则
- **极简免维护**：基于 GitHub Pages 静态托管，无后端服务，零服务器成本，高可用。
- **专为学习设计**：支持最高 3.0x 多档倍速、±15s 重点重听/跳过、断点自动续播记忆。
- **全端体验优秀**：深度适配桌面端与移动端，集成 HTML5 MediaSession API，支持锁屏播放与耳机按键交互。
- **自动化工作流**：脚本一键自动扫描音频目录，解析文件名生成 `playlist.json`，推送 GitHub 后自动构建上线。

### 2.2 数据结构定义

#### `data/playlist.json` 规范
```json
[
  {
    "id": "audio-01",
    "filename": "1.微调与部署：从文字接龙到本地部署.m4a",
    "title": "1.微调与部署：从文字接龙到本地部署",
    "url": "audio/1.微调与部署：从文字接龙到本地部署.m4a",
    "size": 47803122,
    "sizeFormatted": "45.59 MB",
    "order": 1
  }
]
```

#### `localStorage` 缓存规范
- `ai_audio_progress`: 存储各音频断点播放进度 `{ [audioId]: { currentTime: number, duration: number, percentage: number, updatedAt: number } }`
- `ai_audio_playback_rate`: 存储用户习惯倍速，默认 `1.0`
- `ai_audio_last_played`: 上次收听的音频 `id`
- `ai_audio_play_mode`: 播放模式 (`all-repeat` | `single-repeat` | `sequential`)

## 3. 功能特性与交互细节

### 3.1 音频播放引擎
1. **音频格式与兼容性**：
   - 目标格式为 `.m4a`（AAC/ALAC 编码）。
   - 前端采用原生 `<audio>` 标签并使用 `encodeURI` 处理文件名中的中文、空格和特殊标点，确保 iOS Safari、Android Chrome、PC 浏览器正常流式缓冲播放。
2. **学习专享倍速**：
   - 档位：`0.75x`, `1.0x`, `1.25x`, `1.5x`, `1.75x`, `2.0x`, `2.5x`, `3.0x`。
   - 保持 `preservesPitch = true`，加速播放不失真变调。
3. **精准跳转与快进快退**：
   - 界面显式提供 `-15s` 与 `+15s` 独立操作按钮。
   - 音频进度条支持拖拽与精确点击 Seek。
4. **断点记忆与续播**：
   - 播放过程中每秒节流同步当前播放进度至 `localStorage`。
   - 切换音频或重新打开网页时，自动恢复上次时间点。
   - 列表中每一项通过小型进度指示条与百分比文本可视化当前收听进度。
5. **MediaSession 锁屏控制**：
   - 配置 `navigator.mediaSession.metadata`，包含标题、专辑名（"AI学习音频库"）、应用图标。
   - 挂载 `play`, `pause`, `previoustrack`, `nexttrack`, `seekbackward`, `seekforward` 事件，实现手机熄屏下的耳机线控和锁屏界面操控。

### 3.2 界面视觉与响应式设计
- **设计风格**：
  - 深色黑曜石科技背景（`#0b0f19`），辅以渐变蓝紫（`#4f46e5` / `#6366f1`）高亮。
  - 卡片采用高斯模糊半透明毛玻璃效果（Glassmorphism）。
  - 动态频谱波形动画（播放时跳动，暂停时归位）。
- **布局划分**：
  - **PC 桌面端**：双栏布局，左侧为可滚动的音频列表区（支持搜索筛选、状态标签），右侧为核心播放控制面板。
  - **移动端**：自适应单列流式列表，底部悬浮常驻播放控制条，点击可上拉展开全功能大播放器视图。

### 3.3 睡眠与定时停止（辅助学习）
- 快捷定时器：`关闭`、`15分钟`、`30分钟`、`45分钟`、`播完当前`。
- 到点触发平滑暂停，防止睡着后持续消耗电量。

## 4. 音频归档与更新工作流

1. **新音频入库**：
   - 将桌面上的新 `.m4a` 拖拽或复制到本项目的 `audio/` 目录。
2. **生成清单**：
   - 运行本地脚本 `node update-playlist.js`。
   - 脚本遍历 `audio/*.m4a`，自动生成有序的标准 `data/playlist.json`。
3. **推送到 GitHub**：
   - 执行 `git add .`、`git commit -m "update audios"`、`git push`。
4. **自动化部署**：
   - GitHub Actions 监测到 `main` 分支变动，自动把网站资源部署至 `gh-pages` 分支。
   - GitHub Pages 自动更新网站内容。

---

## 5. 边界与异常处理

1. **大音频流式缓冲**：
   - `.m4a` 文件单体约 25~60MB，依赖 HTTP Range Requests 流式缓冲，用户点击后立即缓冲播放，避免一次性全部下载造成卡顿。
2. **特殊文件名与中文编码**：
   - 文件名中包含中文、分号、冒号等字符，URL 路径统一通过 `encodeURI` 转换，并在界面呈现解码后的清晰文本。
3. **跨设备进度同步局限**：
   - 纯前端使用 `localStorage`，单机独立保存进度；未来若需要跨设备（电脑和手机互通进度），可扩展 WebDAV 或云同步，本期以单机独立记忆为主。

## 6. 测试与验证计划

1. **音频加载与流式播放测试**：本地启动 HTTP 静态服务，验证全部 13 个 `.m4a` 文件加载正常、拖动进度条跳转顺畅。
2. **倍速与音频引擎测试**：切换各档倍速（尤其是 2.0x, 3.0x），验证播放速度与音调稳定性。
3. **断点记忆测试**：播放音频到某一时段，刷新页面，验证进度正确恢复并能直接续播。
4. **移动端响应式测试**：模拟手机屏幕视口，验证底部播放条与展开全屏卡片触控交互正常。
5. **部署脚本与 Actions 测试**：验证 `update-playlist.js` 正常生成格式化 JSON，验证 GitHub Actions 脚本语法无误。
